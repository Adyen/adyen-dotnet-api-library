# Repository Guidelines

## Project Structure & Module Organization

- `Adyen/` contains the library source generated by `sdk-automation`. Features
  are grouped by API area, such as `Checkout/`, `BalancePlatform/`, and
  `TerminalApi/`.
- `Adyen.Test/` contains unit tests that mirror the source layout.
- `Adyen.IntegrationTest/` contains tests that call the Adyen test environment.
- `templates-v7/` holds SDK generation templates, and `sdk-generation-log/`
  records generation output.
- `Adyen.sln` is the root solution. General usage documentation is in
  `README.md`; local setup is documented in `DEVELOPERS_GUIDE.md`.

## Build, Test, and Development Commands

Run commands from the repository root:

```sh
dotnet build
DOTNET_ROLL_FORWARD=Major dotnet test Adyen.Test/Adyen.Test.csproj
DOTNET_ROLL_FORWARD=Major dotnet test Adyen.IntegrationTest/Adyen.IntegrationTest.csproj
```

`dotnet build` restores dependencies and builds the solution. Homebrew
currently installs .NET 10, so tests targeting .NET 8 need major-version
runtime roll-forward. Integration tests require credentials and resource
identifiers supplied through environment variables. Never commit credentials.
Tests can also be run with Rider's built-in test runner.

## Generated Source

Never edit files under `Adyen/` manually. Changes to the library source must be
made through the appropriate files in `templates-v7/`, then generated by
`sdk-automation`. Commit the generated output together with the template
change. This keeps generated code reproducible and prevents manual changes from
being overwritten by the next SDK generation.

## Testing Guidelines

Tests use MSTest attributes such as `[TestClass]` and `[TestMethod]`. Place unit
tests in the matching `Adyen.Test/` feature directory. Name test classes with a
`Test` or `Tests` suffix and prefer descriptive
`Given_Condition_When_Action_Then_Result` method names. Use Arrange, Act, and
Assert sections where they improve clarity. Add or update unit tests for every
bug fix or behavior change.

## Commit & Pull Request Guidelines

Use a short, imperative commit subject, for example
`Support RFC 3339 format in DateOnlyJsonConverter`. Create branches from
`main`. Pull requests should explain the problem, the chosen approach, and the
tests added or run. Keep each pull request focused, allow maintainer edits, and
ensure all automated checks pass before requesting review.
